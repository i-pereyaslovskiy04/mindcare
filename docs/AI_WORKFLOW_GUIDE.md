# Выбор моделей и функций Codex / Claude Code для MindCare

Проверено: **2026-10-29**. Это рабочая рекомендация проекта, основанная на
официальной документации. Доступность зависит от клиента, версии, аккаунта и
провайдера. Таблицы ниже — наш выбор стартовых настроек, а не сравнительный
бенчмарк на MindCare. Роли исполнителей и разрешения определяются
[AGENTS.md](../AGENTS.md) и [CLAUDE.md](../CLAUDE.md).

## Четыре отдельных решения

Для каждой задачи выбирать модель, усилие, режим работы и дополнительные функции.
Например: «GPT-6.1 Sol / High / Analysis + Plan / Goal не нужен: результатом будет
одно ТЗ». Рекомендация не означает, что настройки уже переключены.

Модель определяет возможности; усилие влияет на глубину и объём работы. Повышение
усилия разумно при пропущенных проверках, а переход к более сильной модели — при
неверном решении после достаточного исследования. При смене поколения усилие
нужно оценить заново. Это соответствует
[объяснению Anthropic](https://claude.com/resources/articles/claude-model-and-effort-level-in-claude-code).

Названия Analysis, Documentation, Diff review и Implementation в AGENTS.md —
режимы работы в репозитории. Они не являются кнопками клиента. Например, правка
документации выполняется в Documentation mode при обычном режиме клиента.

## Codex: стартовая матрица

В актуальной линейке OpenAI перечислены GPT-6.1 Sol, GPT-6.1 Terra, GPT-6 Astra и
GPT-6 Luna. Sol подходит для сложной работы с кодом; Terra — для текстов и
визуальной работы; Luna — для узких повторяемых задач; Astra — для наиболее
требовательных задач. Названия и доступность сверять по
[Models](https://learn.chatgpt.com/docs/models).

| Задача MindCare | Модель и усилие | Почему и режим |
|---|---|---|
| Найти файлы, собрать список маршрутов по явному критерию | GPT-6 Luna, High | Узкая проверяемая задача; обычный режим |
| Отредактировать готовую документацию, описать макет | GPT-6.1 Terra, Medium | Основная работа с текстом или визуальным материалом |
| Разобрать поток данных, подготовить обычное ТЗ | GPT-6.1 Sol, Medium | Нужны связи между модулями; Plan при неясном контракте |
| Проверить auth, consent, audit, доступ к содержимому, сложный diff | GPT-6.1 Sol, High | Нужны инварианты и негативные сценарии; Analysis / Diff review |
| Разрешить трудную архитектурную развилку, где Sol не справился | GPT-6 Astra, Light (`low`) с дальнейшей калибровкой | Более сильная модель; Plan для сравнения вариантов |
| Особенно трудная последовательная проблема | Sol или Astra, Extra High / Max, если поддерживается | Обосновать дополнительную глубину конкретной нерешённой проблемой |

Для неизвестной задачи сначала оценить её риск. Чувствительный характер MindCare
обосновывает High при анализе доступа, но не при каждой правке текста.

В интерфейсе `Light` соответствует `low`, `Extra High` — `xhigh`; предлагать
только уровни выбранного клиента и модели. OpenAI рекомендует стартовать с High
для Luna и Light для Astra. Max увеличивает глубину работы одной модели, Ultra
использует подагентов; Luna не поддерживает Ultra.
[Источник: Models](https://learn.chatgpt.com/docs/models#pick-a-reasoning-effort).

## Claude Code: стартовая матрица

Текущие версии для рекомендаций: **Sonnet 5.5, Opus 5.5, Haiku 5.5, Fable 5.1**.
Наличие в списке документации не гарантирует доступ в аккаунте. Проверять `/model`
и `/status`; алиас может зависеть от провайдера.
[Официальный список](https://support.claude.com/en/articles/11940350-claude-code-model-configuration).

| Задача MindCare | Модель и усилие | Почему и режим |
|---|---|---|
| Короткий поиск, механическое преобразование без бизнес-логики | Haiku 5.5, Medium | Узкий результат легко проверить |
| Локальная правка или обычная реализация по ясному ТЗ | Sonnet 5.5, Medium | Основной исполнитель; достаточно обычного режима |
| Исправление бага, corrective pass, несколько связанных модулей | Sonnet 5.5, High | Нужны проверки регрессий и пограничных случаев |
| Архитектура, авторизация, согласия, аудит, сложная миграция | Opus 5.5, High | Высокая цена ошибки; Plan, если решения ещё не приняты |
| Самая трудная длительная задача, где возможностей Opus недостаточно | Fable 5.1, High | Рассматривать при доступности и оправданных затратах |
| Трудный остаточный вопрос | Выбранная сильная модель, xhigh; max только с причиной | Повысить усилие на конкретный этап, затем пересмотреть настройку |

У Sonnet 5.5, Opus 5.5 и Haiku 5.5 стандартное усилие — Medium. Поэтому правило
«всегда High» заменено выбором по задаче. High для рискованных работ — решение
MindCare. Поддерживаемые уровни и значения по умолчанию описаны в
[Model configuration](https://code.claude.com/docs/en/model-config#adjust-effort-level).

## Какие функции выбирать

Следующие условия — правила выбора для нашего процесса. Указывать только функции,
которые влияют на текущую задачу, и объяснять пользу от их включения или отказа.

| Функция | Когда рекомендовать в MindCare | Когда достаточно обычного режима |
|---|---|---|
| Plan в Codex и Claude Code | Требования неоднозначны, меняется модель доступа или нужен выбор архитектуры; результат — границы, решения и проверки | Подробное ТЗ уже определяет изменения |
| Goal в Codex | Несколько итераций исследования с измеримым окончанием | Одно объяснение, короткий diff-check, готовый промпт |
| Ultra / subagents в Codex | Можно независимо исследовать backend, frontend и проверки, затем свести выводы | Все шаги зависят от одного решения или одних файлов |
| Ultracode / dynamic workflows в Claude Code | Массовая однотипная работа, широкий аудит с независимой перепроверкой, несколько обособленных направлений | Небольшой баг, локальная правка, тесно связанный рефакторинг |
| opusplan в Claude Code | Нужен сильный план, а реализация после него достаточно понятна для Sonnet | Уже есть план либо и реализация требует Opus |
| ultrathink в Claude Code | Один особенно сложный вопрос внутри обычной сессии | Простая задача или уже достаточное усилие |
| Review в Codex | Проверка конкретного diff после Claude Code в дополнение к Claude Review | Реализации ещё нет; нужен план или объяснение |
| Worktree | Независимая реализация рядом с другой работой над репозиторием | Анализ без изменений, обычная небольшая docs-задача |
| Fast | Задержка мешает интерактивной работе и дополнительная стоимость оправдана | Нужна экономия или более глубокое рассуждение |
| Skills / MCP | Задаче нужны конкретные инструкции, инструмент или источник | Нужные файлы и инструменты уже доступны |

### Plan, Goal и Review в Codex

В поддерживаемом клиенте `/plan` включает планирование, `/review` запускает
проверку изменений, `/goal` задаёт устойчивую цель. В приложении модель и усилие
выбираются через соответствующие элементы интерфейса; команды зависят от
поверхности. Проверять меню `/`, не переносить команды CLI в обычный веб-чат.
[Справочник команд](https://learn.chatgpt.com/docs/reference/slash-commands).

Для Goal нужны результат, критерий готовности и ограничения. Пример цели анализа:
«Проверить все staff-маршруты указанного модуля; для каждого подтвердить проверки
доступа и аудит либо указать доказанный пробел; код не менять». Goal создаётся
только по явной просьбе пользователя; бюджет — только явно заданный. Он не
заменяет разрешение на реализацию. Коротким задачам Goal обычно не нужен.
[Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).

### Plan, opusplan и ultrathink в Claude Code

Для планирования использовать `/plan` или запуск `claude --permission-mode plan`.
Для аудита сохранять READ-ONLY ограничения из CLAUDE.md. Выход из Plan с одобрением
плана позволяет перейти к реализации; выбирать это только в рамках порученной
задачи. [Permission modes](https://code.claude.com/docs/en/permission-modes).

`/model opusplan` выбирает Opus на этапе Plan и Sonnet при исполнении.
`ultrathink` запрашивает углублённое рассуждение для одного хода; фактическое
повышение усилия зависит от клиента и ограничений. Это не запуск параллельных
агентов. [Model configuration](https://code.claude.com/docs/en/model-config).

### Ultracode: учитывать версию

Ultracode организует содержательные задачи через dynamic workflows с подагентами.
Он увеличивает расход; для MindCare сначала указывать независимые направления,
границы записи и способ объединения результатов. Включение Ultracode не отменяет
проверки разрешений инструментов. Однако некоторые подтверждения больших workflow
при нём пропускаются. Не включать его постоянно только ради «максимального качества».
[Dynamic workflows](https://code.claude.com/docs/en/workflows).

- **Начиная с 2.1.284:** `/effort ultracode` включает функцию, сохраняя усилие;
  `/effort ultracode off` выключает её. Изменение усилия само по себе её не выключает.
- **Начиная с 2.1.203:** запуск `claude --effort ultracode` включает функцию и
  устанавливает `xhigh`. Это отличается от переключателя внутри новой сессии.
- До 2.1.284 включение Ultracode было связано с `xhigh`; не давать современные
  команды выключения без проверки версии.

Точные условия:
[Model configuration — Ultracode](https://code.claude.com/docs/en/model-config#adjust-effort-level).

В интерактивном вводе само слово `ultracode` может служить запросом на workflow.
Поэтому в готовом промпте, где функция не нужна, писать «Параллелизм не требуется»,
а команды настройки давать отдельно. Проверять подсветку перед отправкой;
в Windows `Alt+W` снимает срабатывание ключевого слова для текущего ввода.
[Keyword trigger](https://code.claude.com/docs/en/workflows#where-the-keyword-works).

Если нужен промежуточный выбор пользователя, разделить работу на отдельные
workflow: выполнение одного workflow не рассчитано на согласование каждого этапа.
Для аудита поручать агентам только чтение; исправления — отдельная задача.
[Ограничения workflows](https://code.claude.com/docs/en/workflows#behavior-and-limits).

### Разрешения, скорость и изоляция

Auto / Accept edits управляют разрешениями, а не интеллектом модели. Выбирать их
по уже разрешённому объёму работы; не добавлять обход проверок в рекомендации.
[Permission modes](https://code.claude.com/docs/en/permission-modes).

Claude Fast ускоряет поддерживаемые модели Opus за дополнительную стоимость;
это не повышение усилия и не универсальный режим для Sonnet/Fable.
[Fast mode](https://code.claude.com/docs/en/fast-mode).
В Codex `/fast` доступен, когда соответствующий тариф скорости предлагает каталог
моделей. [Команды Codex](https://learn.chatgpt.com/docs/reference/slash-commands).

Worktree отделяет рабочие файлы параллельных задач, но не является отдельной БД.
Для MindCare по-прежнему соблюдать правила тестовой БД, секретов и миграций.
[Worktrees в Codex](https://learn.chatgpt.com/docs/environments/git-worktrees).

## Формат рекомендации и примеры

В первом сообщении достаточно краткой формулировки; в промпте для Claude Code
использовать явные поля из AGENTS.md. Всегда давать причину выбора функций.

- **Разобрать новый staff-доступ:** «GPT-6.1 Sol, High; Analysis + Plan.
  Нужны решения по scope, consent и audit. Goal/Ultra не требуются для одного ТЗ».
- **Реализовать согласованный локальный UI-пункт:** «Claude Sonnet 5.5, Medium;
  Implementation, обычный режим. Plan уже завершён; параллелизм не окупится при
  изменении одного связанного компонента. Выбрать модель и Medium в `/model`».
- **Широкая проверка нескольких модулей:** «Сначала GPT-6.1 Sol, High + Plan для
  перечня модулей и критериев. Затем рекомендовать Goal при явном запросе на
  продолжение до результата; Ultra — только при разрешённом делегировании и
  независимых ветках. Итог — доказанные замечания, без исправлений».

Для новой backend-функциональности рекомендация модели не заменяет обязательный
audit-impact review из AGENTS.md и CLAUDE.md. Реальные ПДн, токены, содержимое
сессий и production-данные не передавать в промпты или внешние источники.

## Проверка доступности и обновление памятки

При проверке **2026-10-29** локальные команды вернули:

- `claude --version`: **2.1.123**;
- `codex --version`: **0.162.0-alpha.17.2** (бинарник из VS Code extension).

Это версии найденных команд PATH, а не доказательство версии другого Desktop/IDE
клиента. Установленный Claude CLI старше приведённых порогов Ultracode. Проверка
не включала обновление программ, изменение настроек или проверку подписки.

Перед рекомендацией новой возможности проверить версию, меню моделей/функций и
официальную страницу. Если клиент отстаёт, назвать доступную альтернативу;
обновление инструмента выполнять отдельной разрешённой задачей. При конфликте
старого анонса с актуальным справочником ориентироваться на справочник для нужной
версии. По Ultracode такая разница уже есть: первоначальная привязка к `xhigh`
больше не описывает все способы включения.

При следующем обновлении пересмотреть таблицы, дату и ссылки, затем согласовать
краткие правила AGENTS.md и CLAUDE.md. Не переносить максимальное усилие на новое
поколение автоматически: сравнить качество на знакомой задаче и выбрать
минимальное достаточное усилие.
[Рекомендации по калибровке](https://academy.claude.com/tutorials/choosing-the-right-effort-level-in-claude-code).
