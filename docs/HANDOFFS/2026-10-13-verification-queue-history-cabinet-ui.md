EventSpec, failure codes и `CHANGE_REGISTRY` не менялись. Дополнение — в

## 1. «Показать отключённых» в `/admin/users`

- Один контрол видимости — Checkbox «Показать отключённых». Селектор статуса
  «Все / Активен / Отключён» убран.
- Параметры собираются из существующих параметров API (`useAdminUsers.visibilityParams`):
  - галочка выключена → `is_active=true`: только активные (`deleted_at IS NULL`
    и `is_active IS NOT FALSE`; исторический NULL — активен);
  - включена → без `is_active`, `include_deleted=true`: активные, отключённые
    и ранее удалённые.
- Backend и смысл `include_deleted` для прочих потребителей не менялись.
- Смена галочки сбрасывает страницу. Опустевшую страницу корректирует общий
  хелпер `shared/lib/pagination.correctedPage`: `lastPage = max(1, ceil(total/size))`,
  пустая страница > 1 → `max(1, min(lastPage, page-1))` (в т.ч. `total=0` → 1).

## 2. Счётчик заявок в меню супервизора

- `GET /api/supervisor/student-verifications/pending-count` → `{"count": N}`:
  - те же критерии, что очередь (`storage._queue_filters` / `_count_requests`), только `count(id)`;
  - router-level `require_role("supervisor")` + запрет impersonation;
  - `Cache-Control: no-store, private`, аудита нет;
  - объявлен ДО `/{request_uuid}`.
- Frontend: `usePendingVerificationsCount` вызывается в `SupervisorLayout`
  один раз (один таймер на sidebar и mobile drawer):
  - загрузка при открытии, опрос 30 с только при видимой вкладке;

  - guard устаревших ответов; ошибка не превращает неизвестное значение в 0;
  - выключен при impersonation / без роли supervisor; unmount останавливает опрос.
- Пункт «Подтверждение студентов» получает `badge` (число, `99+`) и
  `badgeLabel`. `CabinetLayout` ставит `aria-label`

  При 0 бейджа нет.

## 3. Очередь

- `StudentVerificationsPage`:

## 4. История в карточке

- **Источник** — строки `student_verification_requests` пользователя (не audit viewer).
- **Карточка** `GET …/{uuid}` содержит первую порцию: `history: {items, has_more, next_cursor}`.
  - Каждый item — `{uuid, status, faculty, is_current, events}`; заявки и события — от новых к старым.
  - События: `submitted` (самая ранняя заявка), `resubmitted`, `rejected` (проверявший + причина), `approved` (проверявший, без причины).
  - Первая подача определяется подзапросом «самая ранняя заявка пользователя», а не offset/total.
  - `actor: null` — проверявший недоступен (`reviewed_by` SET NULL); UI: «Сведения о проверявшем недоступны».
- **«Показать ещё»** — `GET …/{uuid}/history?before=<uuid>&size=1..50` (по умолчанию 10).
  - Keyset по `(submitted_at, id) DESC`: новая подача между порциями не даёт дублей и пропусков.
  - Курсор заявки другого пользователя или неизвестный → 404.
- **Минимизация:**
  - номер билета прежних заявок не выбирается;
  - причины прежних отказов — только в карточке и порциях истории;
  - `User` целиком не грузится; один SELECT на порцию (карточка — 2 SELECT, `/history` — 3).
- `HistoryItem` переименован в `DecisionOut` (поля прежние) — DTO approve/reject не изменился.

## 7. Переключатель кабинетов

**Причина — ПРЕДПОЛАГАЕМАЯ.** Подтверждена в jsdom и чтением кода, но не в
браузере.

Механизм работает:
- список из `roles[]` (без `selectableRoles`, «Пользователь» у staff есть);
- переключатель есть во всех кабинетах;
- `RoleRoute` проверяет `roles[]`;
- `activeRole` синхронизирует layout.

Почему его не находят: кнопка при нескольких ролях была визуально неотличима
от статичной подписи одной роли. Воспроизведено на прежнем коде: текст
trigger'а «Супервизор▾» против «Супервизор» у статичной метки. Кроме того:
- `aria-label` не было;
- hover задавался белым `rgba` — на светлом фоне навигации не виден;
- на desktop переключатель был только мелким текстом под именем.

Исправление:
- trigger — заметная кнопка «Сменить кабинет» + текущая роль, доступное имя
  «Сменить кабинет (текущий: …)», рамка и hover на токенах, фокус внутрь;
- `variant`: `sidebar` (полная ширина, в т.ч. mobile drawer) и `compact` (topbar);
- при одной роли — статичная подпись без меню;
- панель, Escape, outside click, `choose()` и `activeRole` не менялись;
- второй механизм не создан.

## Доработка (2026-10-14): рассогласование страницы и строк в очереди

**Дефект.** В `useStudentVerifications` номер страницы менялся сразу по
«Далее/Назад», а `items` оставались от прежней страницы до ответа сервера.
Страница показывала «Загрузка…» только при `loading && items.length === 0`,
поэтому старая таблица оставалась на экране вместе с диапазоном и кнопками
«Открыть» — заявки страницы 1 выглядели записями страницы 2.

**Исправление** (только frontend, без бизнес-мутаций):
- Хук запоминает, для какой страницы получены строки (`loadedPage`), и отдаёт
  `items` только при `loadedPage === page`. Состояние выводится из этого
  соответствия, а не из флага запроса, поэтому нет кадра, где новая страница
  показана со старыми строками. Новое поле `pageLoading` — данных для
  текущей страницы ещё нет. Поле `loading` по-прежнему означает «идёт запрос».
- Страница при `pageLoading` показывает «Загрузка заявок…» (`role="status"`)
  вместо таблицы и вместо блока «Ожидают проверки / диапазон»; кнопки
  «Назад/Далее» отключены, пока идёт запрос или нет данных страницы.
- `refetch` той же страницы (после решения) строки не скрывает.
- Ошибка привязана к странице, на которой возникла: после ошибки загрузки
  страницы 2 показывается ошибка, а не строки страницы 1; «Назад» доступен,
  чужая ошибка на странице 1 не остаётся; «вечной загрузки» при ошибке нет.
- Коррекция опустевшей страницы сохранена (в т.ч. `total=0`): при ней
  `loadedPage` сбрасывается, чтобы ранее загруженные строки целевой страницы
  не мелькали до свежего ответа. Защита от устаревших ответов (`requestId`)
  не менялась.

**Тесты.**
