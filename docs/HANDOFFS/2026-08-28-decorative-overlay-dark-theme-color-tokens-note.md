# Цветовые темы: decorative-затемнение поверх картинки и инверсия ролевых токенов

**Дата:** 2026-08-28
**Область:** frontend (`mindcare_web/`) — точечное решение, принятое при
доработке `ServiceCard.jsx` (см. `2026-08-28-service-cards-cms-complete.md`).
Оформлено отдельной заметкой, т.к. вывод касается любого будущего
затемняющего слоя поверх пользовательской картинки.

Механика картинок на **слайдах баннера** (токен `--hero-bg-rgb`, история
бага со `--scrim`) описана не здесь, а в
`2026-08-27-hero-banner-cms-complete.md` §3 — там принято другое решение,
и разница между ними как раз и есть предмет этой заметки.

---

## 1. Задача

Опциональная картинка карточки услуги (`ServiceCard.module.css`,
`.cardVisual.hasImage`) требует затемняющего слоя поверх фото, чтобы
полупрозрачная белая цифра (`.cardNum`) оставалась читаемой независимо от
содержимого картинки.

Формально та же задача, что у баннера (`.heroSlideBg`), — но решается
по-другому, и это не непоследовательность, а разная природа двух блоков
(см. §3).

---

## 2. Находка: ролевой токен может инвертироваться по теме

План изначально предлагал взять для затемнения `--espresso-rgb` — по
аналогии с прочими decorative rgba в проекте. Проверка значений по палитрам
показала, что это сломало бы тёмные темы:

```
dongu-light.css:  --espresso: #16233D;  --espresso-rgb: 22, 35, 61     (тёмно-синий)
dongu-dark.css:   --espresso: #E3ECF7;  --espresso-rgb: 227, 236, 247  (почти белый)
```

`--espresso` — токен **роли** («тёмная поверхность / текст на светлом»), и он
осознанно переворачивается в тёмных темах. `rgba(var(--espresso-rgb), 0.75)`
в тёмной теме дал бы **светлую засветку** поверх фото вместо затемнения —
белая цифра потеряла бы контраст именно там, где слой был нужен.

**Вывод:** токен с «предметным» названием (`espresso` = тёмно-коричневый)
может быть семантически инвертирован в других темах, если объявлен как токен
роли, а не конкретного цвета. Прежде чем использовать любой `*-rgb` токен
для эффекта, который должен выглядеть одинаково во всех темах, нужно
посмотреть его значение в `*-dark.css`.

---

## 3. Решение: фиксированный rgba — и почему здесь оно отличается от баннера

Карточка использует фиксированный `rgba(0, 0, 0, 0.35…0.75)`:

```css
.cardVisual.hasImage {
  background-image:
    linear-gradient(to bottom, rgba(0, 0, 0, 0.35), rgba(0, 0, 0, 0.75)),
    var(--card-image);
  background-size: cover;
  background-position: center;
}
```

Причина, по которой здесь **не** используется тематический токен (в отличие
от баннера, где взят `--hero-bg-rgb`): визуальный блок `.cardVisual`
темонезависим **по дизайну**. Его фон — фиксированные тёмные градиенты
`.accent1`–`.accent5`, а цифра поверх — фиксированный
`rgba(255, 255, 255, 0.18)`; оба уже помечены в этом файле как осознанное
исключение из токенов и одинаковы во всех темах. Затемнение картинки должно
жить в той же системе координат: тематический токен здесь как раз и создал
бы рассогласование — фон полосы остался бы тёмным, а слой над ним в тёмной
теме стал бы светлым.

У баннера ситуация обратная: `.hero` целиком построен на паре
`--hero-bg`/`--hero-fg`, которые переворачиваются согласованно, поэтому там
правильным был именно токен.

Комментарий в CSS явно фиксирует это рассуждение — чтобы следующая правка не
«исправила» rgba обратно на токен ради консистентности с остальным проектом.

Формально это не нарушает правило `mindcare_web/CLAUDE.md` «ни одного raw
hex/rgba в компонентах»: исключение того же класса и с тем же обоснованием,
что и соседние `.accent1`–`.accent5`.

---

## 4. Проверки

`npm run test:contrast` (254 проверки по всем палитрам и режимам, включая
ГОСТ) — 0 нарушений. Важная оговорка: этот чек-лист работает с парами
токенов и **не покрывает** контраст `.cardNum` поверх произвольной
пользовательской картинки — статически он непроверяем в принципе. Здесь
опора на фиксированную нижнюю границу затемнения (0.75 в нижней части
градиента, где расположена цифра) и на визуальный smoke.

## 5. Рекомендация на будущее

При добавлении любого нового затемнения/подложки поверх пользовательского
изображения:

1. **Сначала определить природу блока.** Если окружение блока построено на
   тематических токенах (как `.hero`) — брать токен той же пары. Если блок
   намеренно темонезависим (как `.cardVisual` с фиксированными accent-
   градиентами) — брать фиксированный rgba и комментировать почему.
2. **Не выбирать токен по цветовому смыслу названия.** Проверить фактическое
   значение в `*-dark.css`: ролевые токены инвертируются.
3. **Проверять, что токен действительно определён для нужных тем.** Полезно
   помнить про каскад: `coffee-light.css` — базовый `:root`, остальные
   палитры переопределяют токены через `:root[data-theme="…"]`, а `var()`
   резолвится лениво по текущей теме. Поэтому токен, объявленный только в
   базовом файле через `var(--другой-токен)`, корректно работает во всех
   палитрах — отсутствие его буквального объявления в `dongu-dark.css` само
   по себе ещё не означает, что он там не работает.
