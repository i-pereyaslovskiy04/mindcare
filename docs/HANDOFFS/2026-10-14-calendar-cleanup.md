# Handoff (2026-10-14): Student Calendar Cleanup

Frontend-only, `/student/calendar`. Не полноценный a11y-этап: без ARIA grid,
стрелок, roving tabindex, H1/live-объявлений и A++. Визуальная сетка прежняя.
Основа — READ-ONLY аудит календаря (тот же день). Предыдущий handoff —
`2026-10-14-a11y-basics.md`.

## Главное

- **«Залипшее» окно после смены месяца.** Выбор дня хранился дважды
  (`CalendarGrid.selectedKey` и `CalendarPage.selectedDayKey`/`popupPos`), а
  `prev()`/`next()` меняли только месяц. Теперь `CalendarGrid` controlled
  (`selectedKey` из страницы), смена месяца вызывает `closePopup()`.
- **Сегодня + сессия.** Классы `today`, `sessionDay`, `active`, `out`
  комбинируются (раньше `today` не ставился при сессии). На дне «сегодня + сессия»
  заливка сессии остаётся, число — жирное и подчёркнутое (кольцо занято
  выбранным днём). Сегодня — `aria-current="date"`; hover «сегодня» не
  перебивает заливку сессии (`.sessionDay.interactive:hover`).
- **Mock-события убраны.** `eventsMap` строится только из сессий
  (`useMyAppointments`). Задания и записи дневника из `data/mockEvents.js`
  (фиктивные даты мая 2026) больше не подмешиваются; файл удалён — его
  использовал только `CalendarPage`. Легенда — «Сессия» и «Прошедшая встреча».
  Интеграции календаря с реальными заданиями/дневником нет — это отдельный этап.
  `mockSessions.js` и `SessionPopover.jsx` не используются runtime-календарём,
  не трогались (BACKLOG).
- **Дни (уточнено после review).** Календарь — ещё и быстрый выбор даты для
  формы «Записаться на сессию», поэтому кнопка — **каждый день отображаемого
  месяца**, в т.ч. пустой: `<button type="button">` (Enter/Space нативно),
  `aria-label` «16 октября, пятница» (+ «, есть события», «, выбрано»),
  `aria-expanded`, `aria-controls` на окно (стабильный `id` через `useId`),
  `data-date`. Дни соседнего месяца — текст без фокуса даже с событиями
  (переход — кнопками месяцев). Кнопка визуально = прежняя ячейка (сброс
  `font/margin/appearance`, `width: 100%`).
- **Выбранная дата — одно состояние.** `bookDate` в `CalendarPage` — и значение
  DateInput формы, и подсветка дня (`selectedKey`). Нажатие дня текущего или
  будущего числа подставляет его в форму; ручной выбор в DateInput подсвечивает
  день в отображаемом месяце и закрывает окно прежнего дня; очистка поля снимает
  подсветку. Прошедший день окно открывает (история встреч), но дату в форму не
  ставит — DateInput не допускает даты раньше сегодняшней (`min`); пока окно
  такого дня открыто, кольцо стоит на нём. `CalendarGrid` полностью controlled:
  `selectedKey`, `openKey`, `onDayClick(key, pos)`, `onDismiss()`.
- **Окно «События дня».** Не модальное, открывается для любого дня месяца; без
  записей — «На этот день записей нет». Закрывается повторным нажатием дня
  (дата формы остаётся), «✕», Escape, сменой месяца (дата формы остаётся),
  ручным выбором в DateInput, кликом по дню соседнего месяца/вне календаря.
  «✕» и Escape возвращают фокус на кнопку дня. Данные — всегда дня окна.
- **Подпись «Дата» формы.** `DateInput` получил backward-compatible проп
  `labelledBy` (по аналогии с `Select`): `aria-labelledby="<id подписи> <id
  поля>"`, имя поля — «Дата 16.10.2026» / «Дата Выберите дату». Используется,
  только если не задан собственный `label`; вид поля не менялся.
- **Порядок на телефоне.** Раньше DOM был «левая колонка (календарь +
  предстоящие + история) → правая (форма)», и в одну колонку (≤860px) форма
  уезжала в конец. Теперь DOM: календарь → форма → списки (`.lists`); desktop
  собирается `grid-template-areas` («calendar booking» / «lists booking»,
  строки `auto 1fr`) — форма справа на всю высоту, как прежде. Порядок Tab на
  desktop: календарь → форма → списки.
- **Переполнение карточек «Предстоящие сессии».** Блок статуса/действий
  (`.right`) был `flex-shrink: 0`, badge и кнопки — `nowrap`, карточка не
  переносилась: при узкой карточке (телефон, а также левая колонка на
  861–~1100px) «Отменить» выходил за край. Кроме того, статус стоял в одном
  ряду с кнопками и читался как ещё одно действие.
- **Карточка встречи — новая иерархия (на всех ширинах).** Иконка + тело:
  название → «дата · время · психолог» (полный текст с переносом, без
  многоточия) → нижняя строка: статус-badge слева, группа действий справа
  (`.footer` = `space-between` + `flex-wrap`; `.actions` — `margin-left:
  auto`). На >600px не хватает места — действия уходят под статус, прижатые
  вправо. На ≤600px раскладка детерминированная: `.footer` — колонка, всегда
  три уровня (информация → статус слева → действия справа отдельной
  строкой), независимо от длины статуса. «Подключиться» — primary, «Отменить» — ghost; Badge,
  Button и тексты не менялись. Сдвиг карточки при hover — только
  `(hover: hover)`.
- **«История сессий» — свёрнутый журнал итогов.** Заголовок — `<button>`
  внутри `<h3>` («История сессий · N», chevron, `aria-expanded`/`aria-controls`
  на список с `hidden`); по умолчанию свёрнут, без сохранения состояния. Пустая
  история не рендерится (как прежде). Строка — одна колонка на всех ширинах:
  дата → название → психолог (→ тема) → итог-badge внутри записи (отдельной
  колонки даты и «плавающей» плашки больше нет), без действий.
- **Итог, а не статус записи.** Контракт `Appointment` (backend):
  `pending_confirmation` (создаёт студент) → `confirmed` (психолог,
  `PATCH /api/psychologist/appointments/{uuid}/confirm`) или `declined` (психолог,
  из pending или confirmed); `cancelled` — сейчас только студент, до дня
  встречи (pending при этом soft-delete и из списков исчезает, confirmed
  остаётся видна); `completed`/`no_show` описаны в модели («проведена»,
  «студент не явился»), но **ни один код их для индивидуальных записей не
  выставляет** (maintenance-переход в `completed` есть только у групповых
  занятий). Mapping в `SessionHistory`: `completed` → «Состоялась»,
  `cancelled` → «Отменена», `declined` → «Отклонена», `no_show` → «Неявка»;
  прошедшая `confirmed` — итог неизвестен, badge не показывается (не
  «Состоялась» и не «Подтверждена»). Несостоявшиеся записи остаются, название
  приглушено.
- **Upcoming vs past (`toSession`).** Прошедшая — итоговый статус
  (`completed`/`no_show`/`cancelled`/`declined`) или наступивший `starts_at`
  при любом статусе. Раньше прошедшая `pending_confirmation` оставалась в
  «Предстоящих» с «Отменить», которую backend отклоняет; теперь она в истории,
  `canCancel = false`, итог пустой (как у прошедшей `confirmed`).

## Проверить руками

601 / 600 / 390 / 360px: 7 колонок, кнопка-день того же размера, что пустая
ячейка, без рамки/фона кнопки браузера; окно у левого/правого края не
вылезает; навигация месяца на месте; нет горизонтального скролла. Сегодня с
сессией (подчёркнутое число) в светлой/тёмной теме; Enter/Space/Escape/«✕».
Пустой день → «На этот день записей нет» + дата в форме; день с записью → окно
с записью + та же дата; другой день → обновились и окно, и поле; смена месяца →
окно исчезло, дата формы осталась; выбор в DateInput → подсветка дня.
360 / 390 / 600 / 601 / 768 / desktop: на одной колонке форма сразу после
календаря; карточки предстоящих сессий не шире экрана, статус слева отдельно
от кнопок (≤600px — у всех карточек статус и кнопки на разных строках, 601+ —
одна нижняя строка); нет горизонтального
скролла; desktop — две колонки, форма справа сверху, карточка компактная
(статус и кнопки — одна нижняя строка, разнесённая по краям).
«История сессий» свёрнута при открытии страницы, «· N» видно; Enter/Space
раскрывают; строки компактные, итог — под психологом, длинное имя переносится;
в тёмной теме badge читается.
