# Handoff 2026-11-08 — перенос демо-методик и демо-кампаний на боевой сайт

Ветка `mindcare_vb`. Миграций нет (REGISTRY 157 без изменений). Один скрипт —
`mindcare_api/scripts/migrate_demo_campaigns.py` и файл выгрузки
`mindcare_api/scripts/data/demo_campaigns_bundle.json` (≈ 490 КБ).

## 1. Что переносится

Кампании, чьё название начинается с «Демо:» (5 штук), и их методики:

| Кампания | Методика | Участников |
|---|---|---|
| Демо: ИТО, 100 студентов (синтетические данные) | ИТО Собчик (создаёт `seed_ito_sobchik`, в файле только ответы) | 100 |
| Демо: Самочувствие, 1 курс | Демо: Самочувствие за неделю | 12 |
| Демо: Напряжение и усталость, сессия | Демо: Напряжение и усталость | 10 |
| Демо: Мотивация с кодовым словом | Демо: Учебная мотивация (с нормами) | 14 |
| Демо: Напряжение и усталость, 2 курс (с 1 декабря) | Демо: Напряжение и усталость | 0 (срок начала в будущем) |

Переносятся вопросы, варианты, ключ, `scoring_rules` (нормы, уровни),
`test_interpretations`, участники (ФИО, факультет, специальность, возраст, пол),
их ответы и баллы шкал, сроки кампаний и хеш кодового слова.

## 2. Что НЕ переносится и почему

- **Два ответа в ИТО-кампании пришли из настоящих браузеров** (YaBrowser, Chrome),
  это не синтетика. Экспорт берёт только участников с User-Agent согласия из
  списка `--synthetic-ua` (по умолчанию `mindcare-demo-generator`,
  `Python-urllib/3.13`), остальных отбрасывает и печатает число. Итог: ИТО 100,
  остальные 12/10/14/0.
- SMOKE-тесты, кампания «тест», PHQ-9 и «Демо медиа…» (медиа-файлы этим путём
  не переносятся; методика с медиа, рубриками или тегами останавливает экспорт).
- Токены ссылок: на проде выдаются новые (ссылки видит супервизор в интерфейсе).
- IP участников: у перенесённых согласий `ip_address = NULL`, `user_agent =
  mindcare-demo-import`.
- ФИО в вывод скрипта не печатаются.

## 3. Безопасные умолчания импорта

На боевом сайте каталог видят настоящие студенты, а ссылки принимают ответы.
Поэтому по умолчанию:

- демо-методики `campaign_only = true` — в каталоге студентов их нет, кампании
  по ним работают (`--catalog` — показать в каталоге);
- кампании создаются **закрытыми** (`--keep-status` — как на dev, открытые).

Статус методик — `published`. Владелец методик и кампаний — пользователь,
указанный в `--owner-email` (супервизор или администратор прода).

## 4. Порядок на проде (из `mindcare_api/`)

```bash
alembic upgrade head                       # БД должна быть на head, иначе скрипт откажет
python scripts/seed_ito_sobchik.py         # методика ИТО (идемпотентно)
python scripts/migrate_demo_campaigns.py import --owner-email <e-mail> --dry-run
python scripts/migrate_demo_campaigns.py import --owner-email <e-mail>
```

Файл выгрузки приходит на сервер **релизом из `main`** (прод тянет `origin/main`,
SSH с dev-машины закрыт whitelist'ом): сначала merge ветки `mindcare_vb`,
затем релиз. Скрипт запускает человек с доступом на сервер.

Импорт — одна транзакция. Перед фиксацией шкалы каждого участника пересчитываются
по ключу методики на проде и сверяются с выгруженными (`campaign_response_scales`);
при расхождении, неполном наборе ответов, незасеянном `campaign_consent`,
отсутствующем ИТО, неизвестном владельце или БД не на head — откат и код 1.
Повторный запуск безопасен: кампании и методики, уже существующие по uuid,
пропускаются. `--dry-run` откатывает всё в конце и печатает те же счётчики.

## 5. Обновление выгрузки на dev

```bash
cd mindcare_api
python scripts/migrate_demo_campaigns.py export     # перезапишет scripts/data/demo_campaigns_bundle.json
```

Формат — `format_version: 1`, флаг `"synthetic": true` проверяется при импорте.
Файл содержит синтетические ФИО открытым текстом (при импорте шифруются ключом
прода). Реальные данные в него класть нельзя.

## 6. Аудит

Скрипт аудита не пишет — как `seed_ito_sobchik.py` и seed согласий это системная
загрузка, а не действие пользователя. Новых событий нет, REGISTRY 157.

## 8. Не проверено / риски

- Реальный прогон на проде не выполнялся (доступа нет); проверен только импорт в
  одноразовую БД на схеме head.
- Кодовое слово кампании «Мотивация с кодовым словом» переносится хешем: на проде
  действует то же слово, что и на dev. При необходимости сменить — в карточке кампании.

  попадут записи из браузера, их нужно либо удалить на dev, либо экспорт их
  отбросит и напечатает в отчёте.

  `mindcare_test_3287…` (не мои, прежних прогонов) — удалить вручную.
