# Frontend Checklist

Чеклист перед завершением любой frontend-задачи в MindCare Web.
Проходить перед коммитом.

---

## Shared UI

- [ ] Перед созданием нового UI-контрола проверен `src/components/UI/`.
- [ ] Обычные action-кнопки используют `Button` (не `.btn`, не `.btnPrimary`).
- [ ] True checkbox используют `Checkbox`.
- [ ] On/off переключатели используют `Toggle`.
- [ ] Фильтр-чипы используют `FilterChip`.
- [ ] Статусы / роли / состояния сущностей используют `Badge`.
- [ ] Display-only теги контента используют `Tag`.
- [ ] Выпадающие списки используют `Select`.
- [ ] Множественный выбор использует `MultiSelect`.
- [ ] Feature-specific элементы, которые намеренно не используют shared-компонент, обоснованы и зафиксированы в `docs/UI_TECH_DEBT.md`.

---

## Accessibility

- [ ] У интерактивных кнопок есть `type="button"`, если они не submit.
- [ ] Toggle, FilterChip, Choice-like controls имеют `aria-pressed` или другую корректную семантику.
- [ ] Декоративные элементы (dot, иконка-заполнитель, placeholder) имеют `aria-hidden="true"`.
- [ ] Есть видимый `focus-visible` — не убран через `outline: none` без замены.
- [ ] Display-only элементы (Badge, Tag) рендерятся как `<span>`, не как `<button>`.
- [ ] Интерактивные элементы (Button, FilterChip) рендерятся как `<button>`, не как `<div>` или `<span>`.

---

## CSS

- [ ] Не добавлены новые локальные `.btn*`, `.badge*`, `.tag*`, `.chip*`, `.toggle*`, `.checkbox*` без явного обоснования.
- [ ] CSS Modules не содержат мёртвый код (правила без использования в JSX).
- [ ] Цвета используют CSS-переменные проекта (`var(--espresso)`, `var(--sand)`, etc.), а не случайные hex.
- [ ] Feature-specific стили локализованы в модуле компонента и не дублируют shared UI.
- [ ] Новые CSS-переменные не вводятся без добавления в `styles/variables.css`.

---

## Проверка

- [ ] Проверены все затронутые маршруты в браузере.
- [ ] Проверен responsive (мобильный вид).
- [ ] Запущен `npm run build` — сборка прошла без ошибок.
- [ ] Нет console.error и console.warn в браузере по затронутым страницам.

---

## Финальный отчёт

В конце задачи обязательно указать:

- [ ] Список изменённых файлов (JSX, CSS, API).
- [ ] Удалённые CSS-классы и их количество.
- [ ] Визуальные отличия (если есть, с объяснением).
- [ ] Места, которые намеренно не тронуты (с причиной).
- [ ] Риски (accessibility, визуальные, функциональные).
- [ ] Результат build (bytes delta).

---

## Аудит vs Миграция

Если задача — аудит:
- Только READ-ONLY анализ. Код не меняется. См. `docs/AUDIT_RULES.md`.

Если задача — миграция:
- Менять только то, что явно указано в задаче.
- Не захватывать соседние файлы без явного разрешения.
- Фиксировать исключения в `docs/UI_TECH_DEBT.md`.
